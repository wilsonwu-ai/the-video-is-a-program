# tools: how the explainer video and diagrams are made

The video in `video/` is not drawn by hand and not generated by a video model. It is a program.

- `motion.js` is a tiny timeline (no dependencies). Every animated property is recomputed from scratch for
  any time `t`, so `seek(t)` gives the same picture every time, in any order.
- `video/composition.html` is the film: one `<section class="beat">` per beat, the article's diagrams
  pasted inline, and a timeline that reveals them.
- `render.mjs` drives a headless Chromium through Playwright, calls `seek(t)` once per frame and saves a
  JPEG per frame (1920x1080, 30 frames per second).
- `make_video.sh` turns `video/beats.json` into narration with the Mac's built-in voice (`say`), computes
  the timing of each beat from the audio, renders the frames, and glues everything with ffmpeg into the
  MP4, the captions (`.srt`), the preview GIF and a contact sheet (`contact.png`) used for self-review.
- `svg2png.sh` rasterizes the diagrams (light and dark) with rsvg-convert.
- `checks.py` is the deterministic checker the article was reviewed with (banned words, copied phrasing,
  unknown links, unattributed numbers, section order, word caps).

## Re-render

Requirements: Node 22+, a global Playwright install (`npm i -g playwright` and `npx playwright install
chromium`), ffmpeg, rsvg-convert (`brew install librsvg`), macOS `say` for the narration.

```bash
bash tools/make_video.sh . --preview   # 8 fps, fast; look at video/contact.png
bash tools/make_video.sh .             # full 30 fps render
```

To change a beat, edit `video/beats.json` (captions, narration, minimum length) and the matching section
in `video/composition.html`.
